# Native Android delivery register

Replace the legacy wrapper with a full-featured Kotlin and Jetpack Compose client. Use the [claim and merge workflow](../webapp/docs/MULTI_AGENT_WORKFLOW.md). Each row is independently claimable. Split feature waves into one named module or workflow per PR.

| ID | Work | Acceptance and dependency |
| --- | --- | --- |
| android-release-safety | Investigate the reported Android warning and define the native release baseline. | Capture exact warning text, Android version, distribution source, signer and build/version. Inspect release manifest, dependencies and Play Console findings. Remove WebView, JavaScript bridge, notification listener and any SMS access from the native release artifact. Verify clean install and signed internal-track upgrade with Play Protect enabled. No release until applicable findings are resolved. The reported cause is unverified. |
| android-native-foundation | Set up a Compose navigation shell, native app states, platform-appropriate theme, accessibility and Android CI. | Build and run fixture screens on emulator. Verify navigation, back behavior, configuration changes and keyboard/touch access. Keep any parallel legacy artifact outside the native release. |
| android-native-auth | Implement native Google sign-in using Credential Manager with existing Firebase identity. | Use test accounts to verify existing account continuity, sign-in, cancellation, reload, account switch and logout. Configure OAuth clients for test/release signing and verify account mismatch paths. Can proceed independently of web redirect recovery. |
| android-native-data | Connect native repositories to authenticated backend contracts. | Use server-derived account ownership, versioned responses and shared calculation results. Verify scoped local cache, sign-out cleanup, retries, offline behavior and two-account isolation with fixtures. Production data integration depends on the matching backend endpoints. |
| android-native-ledgers | Deliver dashboard, cash and banking, then cards, transfers and suggested links/categories as separate slices. | Verify read/add/edit flows, period and account filtering, and totals against shared web/backend fixtures. Use user-selected files and manual transaction entry where helpful. |
| android-native-planning | Deliver subscriptions, recurring plans, budgets, loans, installments and rentals in named slices. | Check parity of actual/pending/planned behavior, currency/date semantics and calculation outputs with the shared fixtures. |
| android-native-investing | Deliver broker ledgers, funds, statement preview/import and trading tools in named slices. | Preserve broker, currency and fee boundaries. Use file picker and reviewed imports. Verify parity by workflow. |
| android-native-release | Verify full workflow coverage and release readiness. | Maintain a web/Android capability matrix. Check data migration and upgrade, Android accessibility, current target API, final permissions/dependencies, Play signing, Data safety, privacy and any applicable financial feature declarations. Run internal testing and review Play Console and device results before rollout. |

Use the [shared design reference guidance](../docs/PAGE_TEMPLATE_GUIDE.md). Map each screen to a prototype or current web reference, and use native Compose navigation, system controls and accessibility conventions. For references see [Android Credential Manager](https://developer.android.com/identity/sign-in/credential-manager), [Android app architecture](https://developer.android.com/topic/architecture), and [Play Protect](https://support.google.com/googleplay/answer/2812853).

The native release omits background reading of bank notifications. Preserve server-backed records and verify existing-device upgrade before replacing the legacy app. Retain any needed legacy draft recovery only through an approved, user-initiated migration path.
